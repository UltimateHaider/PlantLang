# 🌿 PlantLang — Chloroplast Core v0.11.0

PlantLang is a structural, strongly-typed, natural-punctuation programming language engineered specifically for the AI-driven development era. Its primary architectural philosophy is to guarantee that source code generated by Large Language Models (LLMs) remains completely deterministic, structurally unambiguous, and deeply human-auditable.

By eliminating traditional curly braces `{}` and non-visible tab-based indentations, PlantLang introduces an explicit **Numerical Depth Matrix Tracking Engine** coupled with a high-performance synchronous execution floor.

---

## ✨ The Core Philosophy

PlantLang is built upon three foundational design pillars:

* **Code Depth (No Braces):** Every block of code begins with an explicit depth number (e.g., `1\` for primary execution, `2\` for sub-operations). This completely eliminates nested brackets `{}` or strict tab-indentations, enabling clear scope auditing.
* **Natural Punctuation:** Statements resemble human literature. An operation is fully sealed using a period `.`, while continuous structural statements can be extended onto subsequent lines using a comma `,`.
* **Pure Human Readability:** Syntactic commands read naturally as standard English instructions (e.g., `CREATE score(NUM) TO 100.`).

---

## 🚀 Key Features Implemented (Simulator & Interpreter Core)

The foundational language core is stable, optimized, and production-ready. The active Chloroplast v0.11.0 engine manages complex execution scopes including:

* **Synchronous Networking Core (`HARVEST`):** Bypasses traditional `async/await` complexities via a background worker thread and OS-level memory locks to stream remote data without blocking the host event loop.
* **Native Test Automation (`SUITE` / `VERIFY`):** Built-in first-class assertion frame supporting isolated expression checks, action harvesting, and native exception tracking written entirely inside PlantLang itself.
* **Data Intertwining (`BRAID`):** Native capability to align multiple parallel collections into paired blocks or zip key/value streams directly into dynamic `MAP` layouts.
* **Object-Oriented Ecosystem (`SPECIES` / `PARENT` / `BLOOM`):** Supports true class structures, method overriding, absolute dynamic state isolation, and inheritance lineage validation via `IS_A`.
* **Advanced Functional Pipelines (`FLOW` / `ACTION`):** Explicit typing parameter passing, deep functional recursion capabilities, and sequential non-mutating stream filters (`SORT`, `UNIQUE`, `REVERSE`, `FLATTEN`).
* **Reactive Data Binding (`PULSE` / `WHENEVER`):** Observable variables that trigger deeply nested responsive handlers automatically upon every mutation.
* **Virtual I/O Streaming (`TAP` / `ABSORB` / `INFUSE` / `SEAL`):** A mock file-system data layout to open paths, stream lines, inject content bytes, and safely close buffers.
* **The 12-Storm Exception Matrix:** 12 strongly-typed systemic exceptions caught natively via localized `WEATHER` / `SHELTER` / `CALM` safety shelters.
* **The PLANT Standard Library:** Immediate structural extensions: PLANT math (11 functions), PLANT strings (10 functions), and PLANT lists (9 algorithms).

## 📦 Architectural Enhancements (v0.11.0 Changelog)

This release focuses on delivering the high-performance concurrent networking pipeline and strengthening the native validation engine:

### 🌾 Synchronous Data Ingestion Engine (`HARVEST`)
* **Deadlock-Free Thread Isolation:** Implemented background Node.js Worker Threads to execute physical network requests, resolving event loop locking by pausing the main execution line using clean OS-level atomic signals (`SharedArrayBuffer` & `Atomics.wait`).
* **Deep Format Type Inference:** Built recursive parsing pipelines that automatically unpack incoming JSON payloads into native `MAP` structures, nested `LIST` matrices, and standard `TX` strings without external parsers.
* **Atmospheric Network Storm Isolation:** Introduced `NETWORK_STORM` to capture physical connectivity drops or timeout thresholds inside native environmental `WEATHER/SHELTER` blocks. Standard HTTP status failures (like 404 or 500) are cleanly handled as data frames inside `result:"status"`.

### 🧪 Advanced Validation Extensions & Bug Fixes
* **Verify Framework Expansion:** Enhanced the native testing engine grammar rules to recognize `HARVEST` as a valid executable block under `VERIFY` evaluation chains.
* **Quoted Map Assertions:** Added native support for evaluating nested quoted keys within testing assertions via `TYPE x:"key" IS [TYPE]` expressions.
* **Storm Whitelisting:** Fixed an issue where `NETWORK_STORM` classifications were omitted from the exception validation registry, ensuring full compatibility across automated regression loops.
