# 🌿 PlantLang — Chloroplast Core v0.13.0 (Compiler Frontend Release)

PlantLang is a structural, strongly-typed, natural-punctuation programming language engineered specifically for the AI-driven development era. Its primary architectural philosophy is to guarantee that source code generated by Large Language Models (LLMs) remains completely deterministic, structurally unambiguous, and deeply human-auditable.

By eliminating traditional curly braces `{}` and non-visible tab-based indentations, PlantLang introduces an explicit **Numerical Depth Matrix Tracking Engine** coupled with a high-performance synchronous execution floor and compiler-grade terminal diagnostics.

---

## ✨ The Core Philosophy

PlantLang is built upon three foundational design pillars:

* **Code Depth (No Braces):** Every block of code begins with an explicit depth number (e.g., `1\` for primary execution, `2\` for sub-operations). This completely eliminates nested brackets `{}` or strict tab-indentations, enabling clear scope auditing.
* **Natural Punctuation:** Statements resemble human literature. An operation is fully sealed using a period `.`, while continuous structural statements can be extended onto subsequent lines using a comma `,`.
* **Pure Human Readability:** Syntactic commands read naturally as standard English instructions (e.g., `CREATE score(NUM) TO 100.`).

## 🚀 Key Features Implemented (Simulator & Interpreter Core)

The active Chloroplast v0.13.0 engine manages complex execution scopes including:

* **Formal Compiler Frontend:** Implements a strict character-by-character Scanner, an isolated Token Stream, and a Recursive-Descent Parser that constructs a strongly-typed Abstract Syntax Tree (AST) before execution.
* **Visual Error Pinpoint Diagnostics (`^`):** Sub-token level terminal error logging that maps exact line and column metrics on syntax violations (`SYNTAX_STORM`), highlighting the exact faulty token/character with visual carets (`^`) driven natively by the parser pipeline.
* **`LISTEN BRANCH` Web Server Core:** Natively parsed block-construct managing concurrent web server bindings, request routing, and sequential evaluation payloads directly inside the language runtime.
* **Synchronous Networking Core (`HARVEST`):** Bypasses traditional `async/await` complexities via background worker threads and OS-level memory locks to stream remote data without blocking the host event loop.
* **Native Test Automation (`SUITE` / `VERIFY`):** Built-in first-class assertion frame supporting isolated expression checks, action harvesting, and native exception tracking written entirely inside PlantLang itself.
* **Data Intertwining (`BRAID`):** Native capability to align multiple parallel collections into paired blocks or zip key/value streams directly into dynamic `MAP` layouts.
* **Object-Oriented Ecosystem (`SPECIES` / `PARENT` / `BLOOM`):** Supports true class structures, method overriding, absolute dynamic state isolation, and inheritance lineage validation via `IS_A`.

## 📦 Architectural Enhancements (v0.13.0 Changelog)

This release marks a massive architectural paradigm shift, transitioning from a flat regex-statement matching loop into a production-grade compiler frontend pipeline while preserving 100% backward compatibility.

### 🛡️ Phase 1: Parallel Compiler Frontend Migration
To safely refactor the core engine without breaking existing test baselines, the new compiler infrastructure was implemented as an isolated, additive, opt-in pipeline alongside the legacy runtime.

* **Pure State-Machine Tokenizer (`core/lexer.js`):** Rewritten from the ground up to scan source code character-by-character. It yields a rich Token Stream embedding strict location metadata: `{ type, value, line, column, depth }`.
* **Recursive-Descent Parser (`core/parser.js`):** Built a formal predictive parser implementing `peek()`, `consume()`, and `match()` logic. Unmigrated statement types safely fall through to a generic `RawStatementNode` to prevent compiler panics.
* **Coordinate-Pure AST Schema (`core/ast.js`):** Architected a formal syntax tree node hierarchy inheriting spatial coordinates from the origin tokens. Successfully migrated statements include: `SHOW`, `CREATE`, `LISTEN BRANCH`, and `RESPONSE`.
* **Additive Interpreter Bridge (`core/interpreter.js`):** Integrated a separate AST evaluation router via `evaluateProgram(ast, soil)` and `runSource()` that natively evaluates typed nodes against the existing local and dynamic Memory Soil infrastructure.

### 🚨 Critical Edge Cases & Compiler Bugs Resolved
* **The Trailing Period Bug:** Fixed a tokenizer lexing collision where statement-terminating periods were being swallowed by numerical constants (e.g., `4.` being consumed as a float). The tokenizer now uses a safe lookahead; a period is only absorbed into a number if followed immediately by a digit (like `3.14`), preserving sentence terminators as standalone tokens.
* **Nested Depth Scope Alignment:** Resolved a block-parsing issue inside `LISTEN BRANCH` bodies where multi-line inner blocks were collapsing into flat top-level nodes. The parser now dynamically consumes line-level `DEPTH` markers before delegating to inner expression loops, preventing token contamination (e.g., text prefixes leaking like `"2 GIVE..."`).
* **Server Payload Evaluation Order:** Fixed a race condition within the web server evaluator bridge. The execution router was refactored to enforce strict sequential node evaluation, ensuring dynamic local allocations (like variables initialized inside the request scope) are fully instantiated *before* the terminal `GIVE...AS RESPONSE` statement triggers.

## 🗺️ Project Roadmap (The Ecosystem Phase)

With the baseline compiler frontend pipeline validated and the server protocol engine fully locked inside the native AST, the development cycle progresses toward deep-layer migrations:

### Phase 1 (Continued): Complete AST Block Migration
* **Full Syntax Tree Adoption:** Systematically migrate remaining high-level constructs (`WEATHER`, `SHELTER`, `HARVEST`, `BRAID`) out of the legacy regex fallback loop and into formal typed AST nodes inside `core/parser.js`.
* **Static Analysis Subsystem:** Introduce a structural compile-time linter using the token stream to detect unreferenced variables and depth violations before the interpreter spins up the execution floor.

### Phase 2: Native Arabic Naming & Localization (Ecosystem Localization)
* **Arabic Native Localization:** Modifying internal identifier regular expressions within the Lexer token matrices to accept complete Arabic alphabet characters for variables, actions, and method naming frames natively.
