# 🌿 PlantLang — Chloroplast Core v0.12.0 (Diagnostics Release)

PlantLang is a structural, strongly-typed, natural-punctuation programming language engineered specifically for the AI-driven development era. Its primary architectural philosophy is to guarantee that source code generated by Large Language Models (LLMs) remains completely deterministic, structurally unambiguous, and deeply human-auditable.

By eliminating traditional curly braces `{}` and non-visible tab-based indentations, PlantLang introduces an explicit **Numerical Depth Matrix Tracking Engine** coupled with a high-performance synchronous execution floor and compiler-grade terminal diagnostics.

---

## ✨ The Core Philosophy

PlantLang is built upon three foundational design pillars:

* **Code Depth (No Braces):** Every block of code begins with an explicit depth number (e.g., `1\` for primary execution, `2\` for sub-operations). This completely eliminates nested brackets `{}` or strict tab-indentations, enabling clear scope auditing.
* **Natural Punctuation:** Statements resemble human literature. An operation is fully sealed using a period `.`, while continuous structural statements can be extended onto subsequent lines using a comma `,`.
* **Pure Human Readability:** Syntactic commands read naturally as standard English instructions (e.g., `CREATE score(NUM) TO 100.`).

## 🚀 Key Features Implemented (Simulator & Interpreter Core)

The active Chloroplast v0.12.0 engine manages complex execution scopes including:

* **Visual Error Pinpoint Diagnostics (`^`):** Terminal error logging that maps exact line and column metrics on runtime/compile panics, highlighting the faulty token with visual carets (`^`) and suppressing raw stack traces.
* **Synchronous Networking Core (`HARVEST`):** Bypasses traditional `async/await` complexities via background worker threads and OS-level memory locks to stream remote data without blocking the host event loop.
* **Native Test Automation (`SUITE` / `VERIFY`):** Built-in first-class assertion frame supporting isolated expression checks, action harvesting, and native exception tracking written entirely inside PlantLang itself.
* **Data Intertwining (`BRAID`):** Native capability to align multiple parallel collections into paired blocks or zip key/value streams directly into dynamic `MAP` layouts.
* **Object-Oriented Ecosystem (`SPECIES` / `PARENT` / `BLOOM`):** Supports true class structures, method overriding, absolute dynamic state isolation, and inheritance lineage validation via `IS_A`.
* **The 12-Storm Exception Matrix:** 12 strongly-typed systemic exceptions caught natively via localized `WEATHER` / `SHELTER` / `CALM` safety shelters.

## 📦 Architectural Enhancements (v0.12.0 Changelog)

This release officially introduces production-grade developer diagnostics and location-aware execution tracking:

### ⛈️ Precision Line/Column Tracking & Visual Caret Render (`core/diagnostics.js`)
* **Coordinate-Aware Lexer:** Upgraded `core/lexer.js` to capture `{depth, text, line, column}` for every parsed statement. The column calculator dynamically accounts for leading whitespaces, indentation spans, and variable-length depth prefixes (`N\`), ensuring perfect token offsets.
* **Multi-Line Anchor Preservation:** Refactored tokenizers to preserve the exact logical coordinate ancestry across multiline statement continuation boundaries (comma linked lines).
* **AST Context Hydration:** Propagated structural metrics across execution workflows. Over 47 internal `storm()` panic invocation sites were refactored to consume and transport dynamic column coordinates natively.

### 🛡️ Centralized Deep-Layer Interception (The Zero-Leak Fallback)
* **EvalExpr Context Wrapping:** Encapsulated evaluation expressions `E()` (evalExpr shorthand) directly inside the structural `_exec` layer to automatically bind spatial locations to deep dynamic evaluation pipelines.
* **Catch-All Statement Fallback:** Implemented a centralized recovery interceptor inside `_execOne`'s singleton `try/catch` block. Any operational anomalies originating from deep, non-location-aware runtime structures (e.g., `ZERO_STORM` inside mathematical evaluators or `LOCK_STORM` inside `Soil.update()`) are safely captured and automatically stamped with the active statement's file row and column before panic rendering.
